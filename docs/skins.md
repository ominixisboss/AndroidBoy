# Making AndroidBoy skins

A skin is a `.zip` file containing a `skin.json` and a few PNG or JPEG images. Import it from
**Skin → Import skin…**, either in the game list's menu or in the in-game menu.

[`example/`](skins/example) is a complete skin to start from. It's generated by
`tools/make_example_skin.py`, but you can also edit its images by hand. To try it, zip the
folder's contents and import the zip.

## skin.json

```json
{
  "name": "Midnight (example)",
  "author": "AndroidBoy",
  "backgroundColor": "#121628",
  "portrait": {
    "image": "portrait.png",
    "pressedImage": "portrait_pressed.png",
    "screen": [90, 140, 900, 810],
    "controls": {
      "dpad": [80, 1180, 360, 360],
      "a": [820, 1220, 170, 170],
      "b": [600, 1330, 170, 170],
      "ab": [770, 1330, 70, 70],
      "select": [300, 1660, 200, 70],
      "start": [580, 1660, 200, 70],
      "menu": [440, 1070, 200, 70],
      "fastForward": [840, 1060, 160, 70]
    }
  },
  "landscape": { "...": "same fields as portrait" }
}
```

| Field | Required | Meaning |
| --- | --- | --- |
| `name` | no | Shown in the skin list. Defaults to the folder name. |
| `author` | no | For your own records. |
| `backgroundColor` | no | Fills the space around the skin when the screen's shape differs from the image's. Also used behind display cutouts. Defaults to black. |
| `portrait`, `landscape` | at least one | The layout for each orientation. If one is missing, the app uses the built-in *Minimal* look for that orientation, on your background colour. |

Each layout has:

| Field | Required | Meaning |
| --- | --- | --- |
| `image` | yes | The skin artwork: everything except the game screen. |
| `pressedImage` | no | The same artwork with every control drawn pressed. While a control is held, its rectangle is copied from this image. Without it, held controls get a light highlight. |
| `size` | no | `[width, height]` of the coordinate space used below. Defaults to `image`'s size in pixels. Set it if you want to use smaller or higher-resolution images without changing the coordinates. |
| `screen` | yes | `[x, y, width, height]` where the game appears. Make it 10:9 (for example 900×810) so the picture fills it exactly. Other shapes work, but the game is centred inside with bars. |
| `controls` | yes | Touch areas, each `[x, y, width, height]`. `menu` is required. |

Control names:

| Name | Does |
| --- | --- |
| `dpad` | 8-way d-pad. Diagonals are the corners between directions, and a finger can slide around it. |
| `up`, `down`, `left`, `right` | Single directions, if you'd rather draw separate buttons. |
| `a`, `b` | The A and B buttons. |
| `ab` | Presses A and B together. Put a small one between the two buttons. |
| `start`, `select` | Start and Select. |
| `menu` | Opens the in-game menu (save states, settings, and so on). |
| `fastForward` | Fast-forwards while held. |

All coordinates are in the skin's own space: the image's pixels, or `size` if set. The skin is
scaled to fit the display, keeping its shape, and centred. So design for a common phone shape,
such as 1080×1920 or 1080×2340 in portrait. Touches slightly outside a control still count, and
a finger can slide from one control to another.

The game screen is drawn *under* the skin's artwork. Any pixels your image has inside the
`screen` rectangle are never shown, so you can leave that area in any colour.

## Limits

- The zip can hold up to 200 files, and 40 MB once unzipped.
- Images bigger than 2400 pixels on their longer side are scaled down when loaded. Coordinates
  still refer to the original size.
- Files must be inside the zip's top folder. They can also be in a single folder inside the zip,
  which is how many tools create zips.

If a skin has a problem, the import fails with a message saying what's wrong. For example, a
control that lies outside the image, an unknown control name, or a missing image.
